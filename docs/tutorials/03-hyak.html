Hyak / Klone: RStudio on the Cluster

Hyak (the Klone cluster) is where the heavy compute happens — RNA-seq, eDNA metabarcoding, big alignments. You'll reach it entirely from your web browser through Hyak OnDemand, and work in the same RStudio you already know from Raven. Your goal today: start RStudio on a Klone compute node with the lab's software container and run one bioinformatics tool.

~1 hourKlone HPCFinish Tutorials 1 & 2 firstUse Hyak when Raven is not enough
Step 1

How a cluster works (read this first)

A cluster is not one big computer. It is thousands of computers shared by everyone at UW, and you borrow a slice of one for a limited time.

  • The machines that do the work are compute nodes. You ask for one by saying how many CPUs, how much memory, and how many hours you need.
  • A program called the scheduler (SLURM) takes your request, waits until a node is free, and gives it to you. When your time runs out, the node goes back to the pool and anything still running stops.
  • Your request is charged to an account (the lab's is srlab) and runs in a partition, a group of nodes. This course uses ckpt, the pool of idle nodes anyone can borrow.
Mental model: SLURM is the host at a busy restaurant. You say "table for two, for an hour," wait to be seated, and when your hour is up the table goes to the next party.
Step 2

Log in to Hyak OnDemand

  1. Off campus? Connect to the UW VPN (Husky OnNet) first. OnDemand does not load from off-campus networks without it.
  2. Open ondemand.hyak.uw.edu in your browser.
  3. Sign in with your UW NetID and password, and approve the Duo prompt.

You land on the OnDemand dashboard. Everything in this tutorial happens from here; you don't need a terminal on your laptop.

First-time access: you must be added to the lab's Hyak allocation (the srlab account) before you can log in or launch anything. If OnDemand refuses you, or srlab isn't offered as an account in Step 3, open a Help Request issue with the platform set to Hyak. This is expected and easy to fix.
Reference: UW's Open OnDemand getting-started guide.
Step 3 · the main event

Launch RStudio on Klone with the lab container

The lab keeps all its bioinformatics software in one container: a single file holding a complete, fixed software stack (R, RStudio, BLAST, aligners, and more). You'll tell OnDemand to start RStudio from that file.

  1. On the dashboard, open the Interactive Apps menu at the top of the page and choose RStudio.
  2. Fill in the form:
    FieldSet it to
    Accountsrlab
    Partitionckpt
    CPUs / memory / hoursStart small: 2 CPUs, 8 GB, 2 hours. Ask for more only when a real analysis needs it.
    RStudio containerChoose Custom, then paste this path exactly:
    /gscratch/srlab/containers/srlab-bioinformatics-container-2bd5d44.sif
  3. Click Launch. Your request appears under My Interactive Sessions as Queued, then Running. Waiting a few minutes is normal.
  4. When it's running, click Connect to RStudio Server. RStudio opens in a new tab, running on a Klone compute node.
When you're done working: go back to My Interactive Sessions and click Delete on the session. That hands the node back instead of holding it until the time runs out.
Reference: UW's RStudio on OnDemand guide shows the form and the Connect button with screenshots.
Step 4

Where files go on Klone

Klone has several storage areas with very different rules. Put things in the wrong place and they get purged or you run out of space.

LocationUse forNote
/mmfs1/home/<netid>small config files10 GB limit — not for data. RStudio starts here.
/gscratch/srlab/lab data & analysesthe lab's shared working space
/gscratch/scrubbed/large temporary workauto-deleted after a set time — never permanent

In RStudio, click the Terminal tab (next to Console) and make yourself a working directory in the lab space, plus a shortcut to it from your home directory so it's easy to find in the Files pane:

mkdir -p /gscratch/srlab/$USER/fish546
ln -s /gscratch/srlab/$USER/fish546 ~/fish546

A fish546 folder now appears in RStudio's Files pane. Keep your Klone work in there.

Handbook: Data Storage & System Organization is the authority on what lives where.
Step 5

Moving data on and off

  • Small files (under a few hundred MB): on the OnDemand dashboard, open Files, go to /gscratch/srlab/<netid>/fish546, and use Upload or Download. Inside RStudio, the Files pane's Upload and More → Export buttons do the same thing.
  • Code: use Git. Clone your course repository into ~/fish546 from the RStudio Terminal, exactly as you did on Raven, and push and pull to move work between platforms.
  • Large datasets: use Globus, a managed transfer service that is faster and recovers from interruptions. Course datasets are already on Klone; see the pinned Provided datasets issue.
Handbook: File Transfers covers Globus in detail.
Step 6

Your tools are already there

Because RStudio is running inside the lab container, every tool in it is available with no installing and no setup.

In the RStudio Terminal:

blastn -version
blastn: 2.x.x+

Any bioinformatics program you use this quarter runs the same way: type it in the Terminal, or call it from a bash chunk in your notebook. Name the container file in your notebook's software statement; that file name pins the exact versions you used.

Handbook: Using containers on Klone explains what's in the lab container and how it's built.
Step 7

Your session is a SLURM job

The form you filled in during Step 3 was a request to the scheduler. OnDemand wrote the SLURM request for you.

Prove it. In the RStudio Terminal:

echo $SLURM_JOB_ID
1234567
hostname
n3148

The first number is your job ID; the second is the compute node you were given. You'll need both for the completion block.

Form fieldWhat SLURM hears
Account srlabwho pays for the time
Partition ckptwhich pool of nodes to use
CPUs, memory, hoursthe size and length of your slice
Sizing matters: ask for too much memory or time and you wait longer in the queue; ask for too little and your session is stopped mid-analysis when it runs out. Start small and increase only when you have a reason. On ckpt, a session can occasionally be stopped early if the node's owner needs it back, so save and commit your work often.
Step 8

Getting unstuck (you will need this)

Everyone hits walls on HPC — it's normal, not a sign you're doing it wrong. Here's how to diagnose and how to ask for help well.

SymptomLikely cause / fix
OnDemand won't loadYou're off campus without the VPN. Connect to Husky OnNet and reload.
Session stays Queued a long timeThe cluster is busy, or you asked for a lot. Delete it and relaunch with fewer CPUs, less memory, or fewer hours.
Session goes straight to CompletedA form problem, usually the account, partition, or container path. Check the path character by character and relaunch.
RStudio suddenly disconnectsYour hours ran out, or a ckpt node was reclaimed. Launch a new session; your files in /gscratch are still there.
command not foundYou picked a standard RStudio container instead of Custom with the lab path. Relaunch with the lab container (Step 3).
Home directory fullData or R packages landed in ~. Move them to ~/fish546 (which lives in /gscratch).
Asking for help the right way gets you unstuck fastest. Open a Help Request issue on the course repository (platform = Hyak) with: what you were trying to do, the form values you used, the exact command, the full error text, and your job ID. Vague "it doesn't work" gets slow answers; a precise report gets fast ones.
